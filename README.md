# 豆包语音跟随 3.2.2 参考音频打断实验版

Android 10 及以上的本地语音辅助工具。在豆包前台的“按住说话”界面检测人声，通过无障碍连续手势按压，停顿后结束同一条按压。

## 下载

在仓库右侧 **Releases** 下载 `DoubaoVoiceFollower-v3.2.2-reference-aec.apk`。GitHub Actions 的 `DoubaoVoiceFollower-stable-apk` 也包含相同构建产物，保留原稳定签名，可覆盖安装。

## 3.2.2 悬浮窗打开豆包

悬浮窗新增“打开豆包”按钮，点击后直接切换到豆包；原有启用跟踪、结束跟踪和关闭悬浮窗按钮保持不变。

## 3.2.1 悬浮窗关闭

悬浮控制右上角的“×”会停止跟踪并关闭悬浮窗。之后可从应用主界面的“显示悬浮控制”重新打开。

## 3.2.0 用户开口打断豆包

本次只处理豆包外放时的语音打断，保留聊天界面和“按住说话”操作，不改为原生通话，不处理开头漏字。以下历史版本章节用于说明旧实现，不代表3.2.0仍用硬件AEC状态放行。

### 使用与验证

1. 先完成麦克风、无障碍授权，设置好灵敏度等选项。建议第一次开启“只检测，不点击”验证声音区分。
2. 点击“授权豆包播放音频”，接受系统捕获授权；系统若要求选择应用，请选择豆包。每次授权仅用于当前捕获会话。
3. 打开豆包聊天界面，启用麦克风跟踪。让豆包单独外放一段回复，观察第三行状态。
4. 只有出现“参考消回声就绪（实验）”，才开始尝试在豆包说话时插话。先核验豆包单独播放不产生人声触发，再核验用户插话可产生触发。
5. 检测验证通过后，关闭“只检测，不点击”，重新授权播放音频并启用跟踪，测试是否实际按住并中断豆包回复。
6. “结束跟踪”、相关设置切换、系统撤销捕获都会停止参考音频。下次语音打断需要重新授权。授权不是永久权限；不在后台偷偷恢复。

### 实现与边界

- 使用Android AudioPlaybackCapture，仅匹配豆包 `com.larus.nova` 的UID以及允许捕获的媒体用途；不捕获其他应用的混音。
- 麦克风与参考音频均为16kHz、20ms帧。按系统单调时间戳跨帧拼接参考样本，短暂等待捕获线程同步，不用任意整帧错位代替对齐。
- 采用SpeexDSP 1.2.1软件回声消除，500ms滤波长度，并使用其残余回声抑制。参考模式不请求本会话的硬件AEC，避免两次处理；系统实际预处理仍由Android决定。
- 有效参考积累至少约1秒、并连续观察到约0.4秒的明显回声衰减后，才允许实验插话。硬件AEC“已开启”不再作为放行依据。参考缺失、无有效播放信号、时间未对齐时不开放播放期间的新按压。
- 回声衰减检查是保守的实验门槛，不等于已经可靠识别说话人。手机位置、外放音量、失真、音频路由和并发麦克风策略都可能影响效果。需要魅族20 Pro真机验证，不声称模拟器测试能证明豆包实测效果。
- 豆包或其播放器若禁止播放捕获，本工具无法获取有效参考，不能绕过限制。此时会显示“未收到有效豆包播放参考”等状态，保留播放保护，而不是假装支持打断。官方规则：[AudioPlaybackCapture](https://developer.android.com/media/platform/av-capture)。
- 捕获仅用于实时消回声：内存最多保留约2秒参考PCM，结束时清空；不创建屏幕画面采集、不保存录音、不上传数据。系统授权对话框可能使用“屏幕共享/录制”等措辞。
- 自动测试增加时间对齐、捕获间断、就绪门槛及原生SpeexDSP合成回声/独立近端声音测试。合成测试不包含真实豆包或厂商音频链路。
- SpeexDSP遵循其BSD许可，完整声明打包在 `assets/SpeexDSP-COPYING.txt`。构建从Xiph官方发布包下载并校验SHA-256。

## 3.1.1 误打断修复

用户真机反馈3.1.0在豆包回复不到1秒时误打断。3.1.0的危险条件是：默认开启实验插话，播放250ms后只要系统报告AEC已启用就允许VAD发起按压。该状态不是实际声学消除质量证明，残余豆包语音仍可能触发。

- 新装和从3.1.0升级均默认关闭外放插话，不继承旧的开启值；灵敏度、结束音量和停顿时间保留。重新手动开启实验插话必须确认误打断风险。
- 正常模式在播放信号持续存在期间始终禁止新按压，AEC已开启也不自动放行。播放信号连续消失800ms后再允许新的语音触发，避免较短播放间隙和尾音。
- 这800ms是播放结束保护，不改变用户说完话的松手时间。已开始的插话录音不会因豆包停止播放后的尾音保护而提前结束。
- 这是保守防误触修复，不是可靠的外放声音分离。代价是正常模式不支持豆包外放期间自动插话。媒体状态和界面标记都漏检时仍有误触风险；请导出诊断记录定位。

## 3.1.0 回声消除

目标设备为用户提供的魅族20 Pro / Flyme 12.6.0.0A / Android 16，尚未完成该真机的声学验证。本版接入系统AEC，不是声纹识别，也不声称已可靠区分用户和豆包。

- 3.1.0默认开启“系统回声消除”和实验插话；3.1.1保留AEC但默认关闭插话。Android 11以上优先使用VOICE_COMMUNICATION并显式关闭录音隐私独占标志；Android 10保留VOICE_RECOGNITION。没有请求音频焦点，不修改全局通话模式或音量。
- 在本工具AudioRecord会话上创建并启用AcousticEchoCanceler，处理后的20ms音频帧再进入原有WebRTC VAD和音量判停逻辑。
- 开关AEC时保持相同的录音源，分别请求开启/关闭本工具会话上的AEC。其他应用优先级可能改变实际预处理，实际通道状态另行记录，不把开关状态当作测试结果。
- 只有AEC可用、已启用、持有控制权且实际capture stream报告AEC时，才允许外放插话。启用不等于声学效果合格；底层是否拿到豆包外放参考，必须真机实测。
- 引擎未确认或用户关闭插话时，检测到播放就暂停自动按压。系统媒体播放信号是全局信号，可能包含其他应用，不能当成“豆包身份识别”。可见播放控件作为补充；两者均不可用时仍可能漏检。
- 只有手动确认开启实验插话时，播放开始250ms后才可能允许插话，仍取决于AEC实际效果；没有声纹或播放录音参考的额外软件分离。3.1.1正常模式不在播放期间放行，结束保留800ms保护。
- 增加“只检测，不点击”，该模式仍检测处理后的声音，但不屏蔽播放期间的检测结果，且禁止发起任何按压，方便比较开关AEC的效果。
- 三个新开关修改时停止本轮跟踪并结束原按压，重新启动后使用新设置。灵敏度和停顿设置继续实时生效。
- 诊断记录包含系统版本/Build、AEC状态、输入设备类型、请求和实际录音源、媒体播放、音量、VAD、判停与手势状态；不保存录音，不读取聊天文字。

### 魅族手机验证

先开启“只检测，不点击”。在相同手机位置、外放音量和灵敏度下，分别关闭和开启系统回声消除，每次改设置后重新启用跟踪：测试用户单独说话、豆包单独说话、豆包说话时用户插话。观察“检测到说话”并导出诊断记录。只有豆包单独播放不误触、用户单独说话和插话可识别，才通过这一项验证。

再关闭“只检测，不点击”测试实际按住、停顿松手和并发麦克风。AEC引擎开启不等于验证通过；如果豆包开始录音后工具被系统静音，会暂停并请求结束按压，不能把系统静音当成正常说完。若外放仍误触，可关闭实验插话回到播放保护，或使用耳机减少声学回声。

系统接口：[AcousticEchoCanceler](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler)、[实际录音预处理](https://developer.android.com/reference/android/media/AudioRecordingConfiguration#getEffects())。

## 3.0.1 手势修复

3.0.0重复提交没有移动、没有抬起事件的静止续接。Android的MotionEventInjector会拒绝空事件列表，而原有按下可能仍保留，导致快速失败和录音界面不退出。参考：[AOSP MotionEventInjector](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/services/accessibility/java/com/android/server/accessibility/MotionEventInjector.java)。

本版仅提交一次保留触点的DOWN，说完后继续同一个笔画提交一次UP，按住期间不再提交续接。失败后先尝试结束原按压，再暂停，不会因为仍有人声而连续重试。增加Android 10和15模拟器测试，验证旧实现空续接被拒绝、新实现保持按压后抬起以及连续三轮对话。模拟器使用测试触摸界面，不包含豆包；调试测试组件不会进入发布APK。

使用原有固定签名和应用 ID，2.x 稳定签名版可覆盖安装。系统仍可能因厂商后台限制、手动撤销或系统设置而关闭无障碍服务；应用不能自动替用户授权。

## 3.0 重写内容

- 使用 [android-vad 的 WebRTC VAD](https://github.com/gkonovalov/android-vad/tree/2.0.10) 进行本地人声判断，16kHz / 20ms 固定音频帧。不是语义识别，也不能识别具体说话人。
- 检测到连续60ms人声且达到启动音量后请求按压。灵敏度1到10，默认6；相比2.2降低了启动音量下限。
- 非人声或音量低于实际结束线，持续达到用户设置的0.2到2秒后请求松手，默认0.4秒。VAD本身的尾部判定、手势剩余时间和系统调度会增加实际延迟。
- 自动模式在非人声帧持续学习底噪，包括按住期间。结束音量设置仍为0.2%到3%，实际结束线被限制在启动线的80%以内，防止两个设置相互冲突；悬浮窗显示实际生效值。
- 音量和VAD仍可能误判强噪音、弱声或其他人的声音；不能保证每次都与人的语义停顿一致。
- 声音与按压状态统一在主线程处理，声音采集和界面读取分别在后台线程工作。使用单调时钟和会话/手势编号，忽略旧会话的音频及过期手势回调。
- 按压被系统拒绝后暂停；异常回调先结束原按压并核验界面，不自动连续重试。下一句话在上一条松手完成前不会新建手势。
- 一次按下保持触点，结束时继续原笔画并置为不再延续。删除原来的“新建点击强制松手”和空续接。缺失回调时最多再尝试一次结束原笔画，失败则停止并提示手动结束。
- 松手回调后检查豆包界面恢复“按住说话”、且录音标记消失。无法确认时暂停自动操作，不声称“发送成功”。
- 一次说话最长30秒，达到上限后必须等待停顿才能重新触发，避免持续噪音无限续按。
- 检测系统录音静音、读取错误、800ms数据中断，停止跟踪并请求结束按压。不能把系统静音当作用户正常停嘴。
- 只匹配豆包包名 `com.larus.nova` 的前台窗口；锁屏、其他应用或过期窗口状态不允许新建按压。短暂未知状态最多容忍450ms已存在的按压。
- 必须找到真实可见的“按住说话”节点；不再猜底部坐标。悬浮窗遮挡目标时不按压。
- 3.0版播放拦截依赖可见播放标签；3.1已改为上文描述的AEC插话和保守播放保护。

## 使用

1. 安装APK并打开应用，授予麦克风权限，在系统设置开启“豆包语音跟随”无障碍服务。
2. 返回应用，点击“打开豆包”，进入“按住说话”输入模式。
3. 点击悬浮窗的“启用麦克风跟踪”。点击“结束跟踪”会停止检测并请求结束现有按压。
4. 主界面可设置灵敏度、结束音量、自动底噪适应、停顿多久松手。
5. 遇到异常，在主界面点击“导出诊断记录”，记录包含当前版本、Android版本、设备型号、音量、VAD及手势状态，不包含聊天文字和录音。日志在内存保留最近300条，服务重启后清空。

## 兼容性边界

豆包版本如果不向无障碍公开“按住说话”或录音状态节点，应用会提示无法找到或无法确认，不能保证适配。应用分身、其他包名、锁屏及后台豆包不支持自动按压。

3.1可以在缺少播放标签时利用全局媒体状态保护，但无法确定播放来自哪个应用。部分音频路径可能不被此信号覆盖；AEC也可能缺少外放参考或效果不足。扬声器回复仍有被当成人声的风险，不能通过音量或VAD保证区分用户和扬声器中的人声。

Android存在并发麦克风访问规则，无障碍悬浮窗并不保证每台设备上两个应用都能持续收到声音。如果系统报告录音被静音，本版会明确停止，不通过猜测继续控制。相关规则：[Android Sharing audio input](https://developer.android.com/media/platform/sharing-audio-input)。

## 构建与验证

GitHub Actions运行 `testDebugUnitTest lintRelease assembleRelease`，并验证APK签名。测试覆盖结束计时、非人声底噪、设置冲突、30秒重新待机、旧音频帧、失败重试、迟到回调、松手期间下一句话、前台限制和缺失手势回调。

自动测试验证独立状态逻辑，不等于真实手机与豆包界面的端到端验证。需要在目标手机核验并发录音、识别准确率、连续手势和可访问节点。

签名来自仓库Secrets：`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。私钥不在仓库中。

## 隐私与依赖

应用没有联网权限，不保存或上传音频。WebRTC VAD由 `com.github.gkonovalov.android-vad:webrtc:2.0.10` 提供，遵循其MIT及上游WebRTC许可；模型计算在手机本地完成。
